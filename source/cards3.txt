Q: Walk through the DQN algorithm.
P: 1. Look at the screen and pick a move, mostly the best one, sometimes random.
2. Write down what happened in the replay notebook.
3. Pull a random handful of past moments from the notebook.
4. For each, aim the network's guess at "reward plus the frozen copy's best next guess".
5. Every so often, update the frozen copy. Repeat.
A: 1. Initialise replay buffer $\mathcal D$, network $\mathbf w$, target $\mathbf w^- = \mathbf w$.
2. Each step: choose $a$ $\varepsilon$-greedily from $\hat q(s,\cdot,\mathbf w)$, act, observe $r, s'$, store $(s,a,r,s')$ in $\mathcal D$.
3. Sample a random mini-batch from $\mathcal D$.
4. Target $y_j = r_j$ if $s'_j$ is terminal, else $r_j + \gamma\max_{a'}\hat q(s'_j,a',\mathbf w^-)$.
5. Gradient step on $(y_j - \hat q(s_j,a_j,\mathbf w))^2$, updating $\mathbf w$ only.
6. Every $C$ steps set $\mathbf w^- \leftarrow \mathbf w$.

Q: What policy objectives J(theta) can you optimise?
P: $J(\theta)$ is the "how well am I doing" score that we push upwards. For games with an end, it is the expected total score from the start. For tasks that never end, it is the average reward per step, or the average value over the states you visit.
Pick the one that fits the task. They all point the improvement in the same direction.
A: - **Episodic, start value**: $J_1(\theta) = v_{\pi_\theta}(s_1)$.
- **Continuing, average value**: $J_{avV}(\theta) = \sum_s d^{\pi_\theta}(s)\,v_{\pi_\theta}(s)$.
- **Continuing, average reward per step**: $J_{avR}(\theta) = \sum_s d^{\pi_\theta}(s)\sum_a \pi_\theta(a\mid s)R(s,a)$.
All three give the same gradient direction up to a constant, so the policy gradient theorem covers them all. We **maximise** with gradient ascent $\theta \leftarrow \theta + \alpha\nabla_\theta J$. Frameworks minimise, so you code the loss as $-J$. Forgetting the sign is the classic bug.
K: policy objective, start value, average reward, gradient ascent

Q: State the policy gradient theorem and why it is so important.
P: The **policy gradient theorem** says: to improve, make moves that turned out well more likely, and moves that turned out badly less likely, weighted by how good they were.
The important part is that you do not need to know how the world works. You only need the moves you made and how they went.
A: $$\nabla_\theta J(\theta) = \mathbb E_{\pi_\theta}\left[\nabla_\theta\log\pi_\theta(a\mid s)\; q_{\pi_\theta}(s,a)\right]$$
Why it matters:
- No derivative of the state distribution $d^{\pi}(s)$, even though changing $\theta$ changes which states you visit.
- No dynamics model needed: dynamics terms vanish when you differentiate the log-probability of a trajectory.
- Estimate it from samples: run the policy, average score times return.
- Any estimate of $q$ works: MC return (REINFORCE), TD error (actor-critic), advantage (PPO).
K: policy gradient theorem, score function, model-free

Q: Explain actor-critic and why the TD error estimates the advantage.

- $\delta = R + \gamma\hat v(S',\mathbf w) - \hat v(S,\mathbf w)$
- Critic: $\mathbf w \leftarrow \mathbf w + \beta\,\delta\,\nabla_{\mathbf w}\hat v(S,\mathbf w)$
- Actor: $\theta \leftarrow \theta + \alpha\,\delta\,\nabla_\theta\log\pi_\theta(A\mid S)$

@card w11
I: mcts
Q: Walk through the four phases of MCTS.
P: 1. **Selection:** walk down the tree you have built so far, choosing promising moves.
2. **Expansion:** add one new move to the tree.
3. **Simulation:** play randomly from there to the end, like a quick imaginary game.
4. **Backpropagation:** carry the result back up and update every move on the path.
Repeat thousands of times and the best move becomes clear.
A: Repeat until the budget runs out:
1. **Selection**: from the root, follow the tree policy (UCT) down through fully expanded nodes until reaching a node with an untried action.
2. **Expansion**: unless terminal, try one untried action and add the resulting node.
3. **Simulation (rollout)**: from the new node play a default policy (often random) to a terminal state. Rollout nodes are not stored.
4. **Backpropagation**: send the return back up the visited path, incrementing $N(s,a)$ and updating $Q(s,a) \leftarrow Q(s,a) + \frac{1}{N(s,a)}(G - Q(s,a))$ with $G \leftarrow r + \gamma G$ at each level.
Then play $\arg\max_a Q(\text{root},a)$, observe the real next state, keep that subtree and discard the rest.

Q: What is UCT and what does each term do?
P: **UCT** picks which branch to explore in MCTS. It adds two things: how good a branch has been so far (exploit), and a bonus for branches tried only a few times (explore).

A: UCT is UCB1 used for selection inside the tree:

(the lecture uses the simpler $Q + c\sqrt{\ln N(s)/N(s,a)}$).
- $Q(s,a)$: exploitation.
- Square root: exploration bonus, large for actions rarely tried relative to their parent.
- $C_p$: exploration constant. With rewards in $[0,1]$ and $C_p = 1/\sqrt2$, UCT converges to minimax in two-player zero-sum games.

Q: Value iteration vs MCTS: which and when?
P: **Value iteration** computes values for every state, so it suits small problems with known rules where you want a complete plan.
**MCTS** only thinks about the current position, so it suits huge problems like Go, where computing everything is impossible.
A: - Value iteration: exhaustive over all states, higher cost, but the policy works from **any** state. Solve once, reuse many times.
- MCTS: only explores states reachable from the current one, lower cost per decision, but must re-plan online at each new state.
Pick VI for small MDPs with a known model that you will query from everywhere. Pick MCTS for huge state spaces with a simulator where you only need good decisions from where you are.
K: value iteration, MCTS, offline, online
